# Deck Organizer

把提案 deck 拆到「页」入库 → **人工打标签** → 检索 → 挑页组成新案例。

不是在线 PPT 编辑器。系统只管三件事：**存哪些页、每页是什么、把选中的页拼起来。**

---

## 用法

```bash
pip install -r requirements.txt

# 1. 导入：拆页 + 抽标题 + 生成缩略图（不打任何标签）
python3 -m deckorganizer import 你的*.pdf --out library

# 2. 生成工作台页面，在浏览器里人工打标签
python3 -m deckorganizer build --library library --out build/workbench.html

# 3. 打完标签，从工作台导出 JSON，写回库里
python3 -m deckorganizer apply --library library --edits deck-organizer-edits.json

# 4. 检索
python3 -m deckorganizer search --tag 北美 --tag CES --library library
python3 -m deckorganizer search 美的 --library library

# 5. 挑页组成新案例（无损）
python3 -m deckorganizer compose --library library \
  --pages "C:41,C:42,C:43,B:31" --out 欧洲家电案例.pdf
```

## 为什么标签靠人打

自动打标试过，做不对，所以拿掉了。

词表能抽出来的是一页**提到了什么**，而不是这一页**是什么**。同一批词会同时出现在
三种页面上：一个真实案例、一页介绍该项服务的能力说明、一张章节分隔页。
再加上「融资」被算成金融行业、方法论页蹭到两个不相干行业这类误报，
结果是一个看起来填满了、实际不能信的库 —— 比空着更糟。

**导入时不打任何标签。** 标签目录预置了一份草稿词表（都来自这几份 deck 的真实内容），
让第一遍打标基本是点选而不是打字，但每一条都能改、能删、能新增。

## 标题是怎么抽的

标题不是「第一行文字」，而是**版面上最大的那行字**。

按阅读顺序取第一行，抽到的往往是正文首句 —— 实测三份 deck 里，很多页拿到的是
「2026年6月，我们支持道通科技与联合联合国开发计划署（UNDP）及坦…」这种截断的句子。
改成按**字号 + 位置 + 成行**识别之后，同一页得到的是「支持道通科技与联合国开发署坦桑尼亚清洁能源项目」。

三处需要留意的细节：

- **按行取，不是按字号取**。标题里常混着不同字号（「我们服务的客户已超过 **500** 家」，
  数字比字大得多）。只取最大字号会只剩「500」。
- **页码要过滤，标题里的数字不能过滤**。判据是字号：页码是正文字号或更小。
- **全是数字的不是标题**。数据条（「277M 17篇」）会被判低置信度，交人工确认。

168 页里 161 页拿到了可信标题，7 页（目录、纯数据条、复杂版面）标记为待确认。

## 工作台

发布出来的页面是一个**实时共享文档**：谁改了标题、打了标签、动了标签目录，
改动自动保存并同步给所有打开这个页面的人。不需要本地起服务，也不需要各自维护一份。

### 三个模式，各管各的

打标签和挑页组 deck 是两件不同的事，用的是两套互不干扰的选择：

**左边栏的角色跟着模式走**，不是一个开关。同一列标签，在打标签模式里是「打上去」，
在组页模式里是「筛出来」，所以两个模式的配色和文案完全不同 —— 紫色是在改数据，青色是在看数据。

| 模式 | 左边栏 | 点一张页面 |
|---|---|---|
| **打标签**（紫） | **选一个标签**（单选）去打 | 打上/取消该标签。没选标签时则打开详情面板 |
| **组页**（青） | **多选标签**做筛选 | 加入待组页清单，卡片显示顺序号 |
| **查重**（青） | 多选标签做筛选 | 打开详情面板对比相似页 |

切换模式会清空左边栏的选择 —— 否则会带着上个模式的筛选进来，页面被藏了却没有任何提示。

### 一个标签，多选页面

打标签时**标签是单选的**（当前在打哪个），**页面是多选的**。三种选法：

- 一张张点
- 点第一张，按住 <kbd>Shift</kbd> 点最后一张 → 中间整段一起打
- 先用搜索或视图筛出一批 → 点顶部「给当前 N 页全部打上」

标签上带计数，能看出每个标签已经打了多少页。已带当前标签的页面会高亮加勾，一眼看得出刷到哪了。

每张卡片右上角有 <b>i</b> 按钮，任何模式下都能打开该页详情面板（改标题、逐个点标签、确认标题、处理相似页），方向键 ←→ 翻页。

### 标记会自己消失

「标题待确认」和「相似页」是**问题**，答了就该消失：

- 在面板里点「✓ 标题已确认」→ 黄标记变成绿色的「标题已确认」
- 点「保留」或「标记删除」→ 紫色的「相似页」变成「已保留」/「已标记删除」

这些判定和标签一样是共享的，会跟着导出 JSON 出来。

### 标签栏

左侧抽屉，点边上的把手滑动展开或收起。它是**把页面推开**，不是盖在上面 —— 展开时一页也不会被挡住。

| | |
|---|---|
| 改标题 | 点标题直接改 |
| 标签目录 | 新建/重命名/删除**类别**；新建/重命名/删除**标签**；切换单选/多选 |
| 重命名联动 | 改标签名，所有用到它的页面同步改 |
| 删除联动 | 删标签，所有页面上的该标签一并移除 |
| 筛选 | <b>◎</b> 按标签筛选，或按未打标 / 标题待确认 / 全文搜标题 |
| 导出 | 导出 JSON，用 `apply` 写回库 |

筛选、选中、搜索、抽屉开合这些是**每个人自己的视图状态**，不会互相干扰；
标题、标签、目录、查重判定才是共享的。

## 查重

导入时自动比对全库，把疑似同一页的不同版本聚成组，交人工确认 —— **不自动删任何东西**。
删除是唯一在界面上撤不回来的操作，所以不提供。

判据是两个独立信号：

- **文字**：同一个案例在另一份 deck 里重讲一遍，措辞基本不变，版面却会飘（标题换行位置变了、logo 挪了位）
- **版面**：图多字少的页面靠感知哈希认

用字符二元组算相似度，不按空格分词 —— 中文按空格分词会把整句话变成一个 token，
每次比较非 0 即 1。

有一条规则值得单独说：**文字少的页面，光看版面像是不够的**。
章节分隔页共用同一套版式、各自只有几个字，只按版面判会把「01 产品传播案例」
和「02 企业传播案例」判成同一页。所以文字少的页面必须版面几乎相同**且**文字也对得上。

实测三份 deck：**23 组 47 页**，手工核对过的 17 对重复全部命中，分隔页不再误报。

## 数据放在哪

```
library/
  archive/A.pdf B.pdf C.pdf     原始文件，只读留档
  A/thumbs/*.jpg                每页缩略图
  index.json                    页面、标题、标签、标签目录、使用记录
```

**页不会被拆成独立文件。** 一页就是「哪个文件的第几页」，组页时直接从原件拉。
试过给每页物化一个 PDF：28MB 的源变成 238MB，因为每个单页会把共享字体和图片各复制一份，
而 `insert_pdf` 从原件读任意一页一样快。现在整个库 33MB，其中 28MB 是原始文件本身。

组页是**无损**的：页面被复制，不是重绘。实测 10/10 页与源文件像素级一致。

```

标题        161 页可信，7 页待人工确认
查重        23 组 47 页；已知 17 对重复全部命中
组页保真    10/10 页与源文件像素级一致
库体积      33MB（28MB 是原始 PDF）
```
